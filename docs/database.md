# Database

Postgres on Supabase. Migrations live in `supabase/migrations/` and are applied **in order** (001 → 007) in the
Supabase SQL editor. Every migration is safe to re-run. Never edit an applied migration; add a new numbered file.

| Migration | Adds                                                                                                                                |
| --------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| 001, 002  | Core tables, 1024-d vectors                                                                                                         |
| 003       | All ATS/board providers, richer jobs, the server-side Vault (`match_scores.status`), `pipeline_runs`                                |
| 004       | Target roles (`user_profiles.current_role`)                                                                                         |
| 005       | Jobicy / The Muse / Adzuna / Jooble, C2 · OPS stages, `tailored_resumes` (OVERCLOCK)                                                |
| 006       | Resume version on applications, `gmail_links`, `ops_events`                                                                         |
| 007       | Teamtailor, discovery queue (`discovered_companies`, `source_state`), `jobs.verified_at`, Vault default 80, auto-OVERCLOCK settings |

| Table                  | Key columns                                                                                                                                                                                                 | Notes                                                                                                                            |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `companies`            | `name`, `ats_provider`, `ats_identifier`, `category`, `last_scraped_at`, `website`, `source`, `funding_stage`                                                                                               | Seeds come from `src/lib/scraper/companies.ts`; discovery adds more (`source` = `startupmap` / `import`). `custom` = not scraped |
| `jobs`                 | `(company_id, external_id)` unique, `title`, `description`, `location`, `skills[]`, `employer`, `posted_at`, `content_hash`, `is_active`, `verified_at`                                                     | `employer` is set for job-board sources. The vector lives in Pinecone under the job `id`                                         |
| `user_profiles`        | `id` (Clerk user id), `skills[]`, `location`, `is_fresher`, `experience_years`, `resume_text`, `resume_embedding`, `current_role`, `vault_min_score`, `auto_vault`, `auto_overclock`, `overclock_daily_cap` | `location`: comma-separated cities, may contain `Remote`; `current_role`: comma-separated target roles                           |
| `user_dream_companies` | `(user_id, company_id)`                                                                                                                                                                                     |                                                                                                                                  |
| `match_scores`         | `(user_id, job_id)` unique, `score`, `reasoning`, `section`, `status`, `auto_saved`, `stage`, `applied_at`, `notes`, `resume_version_id`                                                                    | The Vault and C2 · OPS. `status`: `new` / `saved` / `applied` / `dismissed`                                                      |
| `tailored_resumes`     | `(user_id, job_id)` unique, `content` (JSON), `base_score`, `projected_score`                                                                                                                               | OVERCLOCK output; one per user and job                                                                                           |
| `gmail_links`          | `user_id`, `email`, `refresh_token_enc`, `last_synced_at`, `last_error`                                                                                                                                     | The refresh token is AES-256-GCM encrypted with `GMAIL_TOKEN_KEY`                                                                |
| `ops_events`           | `(user_id, external_id)` unique, `match_id`, `source`, `kind`, `summary`                                                                                                                                    | The application timeline (e.g. a rejection read from Gmail)                                                                      |
| `discovered_companies` | `(source, source_ref)` unique, `status`, `priority`, `company_id`, `note`                                                                                                                                   | Startups waiting for RADAR to find their ATS board                                                                               |
| `source_state`         | `source`, `synced_at`, `notes`                                                                                                                                                                              | Per-directory crawl state: 48h sync time, resume cursor, pause                                                                   |
| `scrape_logs`          | `company_id`, `status`, `jobs_found`, `error_message`                                                                                                                                                       | One row per company per run                                                                                                      |
| `pipeline_runs`        | counts per run, `notes` (failures)                                                                                                                                                                          | One row per `/api/cron` call; the dashboard's "jobs refreshed" reads it                                                          |

All server code uses the service-role client (`src/lib/supabase/client.ts`), so row-level security
policies only matter if the browser ever queries Supabase directly. Features whose migration has not been run
degrade gracefully (`isSchemaMissing` fallbacks) instead of breaking the page.
